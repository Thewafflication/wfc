# MP-0010: Distribution, Libraries and Command Line

**Content type:** Milestone plan

**Status:** In progress (started on the owner's instruction, 2026-10-29)

## Goal

Make WFC installable and its libraries independent, versioned and linkable
either way, with a command line that explains itself.

**Windows 2000 and later is deferred (owner, 2026-11-01): WFC builds with
the current MSVC and the full runtime is the default; the work below stays in
the tree as an opt-in (`--target win2000`, `WFC_TARGET=win2000`).** It was a
goal of this milestone. The programs WFC
writes should run on Windows 2000 and later without the Microsoft C++
runtime. Done so far: console programs of x86 machine code run on `wfcw2k.exe`,
a small runtime in C built with TinyCC and WCRT (`wfc build --target win2000`,
the default of an x86 wfc), with Variants (the operators and conversions of
the interpreter ported to C, and arrays of Variants). Still to do, in this
order: the library functions on Variants (`Format`, `Split`, `CDate` and the
rest of service 77) and Variant arrays in the C runtime, then classes, files, dates and the other library statements, and last forms,
the controls and `wfc.exe` itself, which need a C++ compiler and library that
target Windows 2000 (the toolchain track of the libraries). Every step is
checked against the 64-bit native run and by WCRT's Windows 2000 import gate.

## Scope and decisions

| Item | Decision |
| --- | --- |
| Issues | Issues 1 to 5 of `Thewafflication/wfc` fixed and closed (`corpus 200`). |
| Libraries | `lib/wfc-vbrun` (`wfcvbrun.dll`, `wfcvbrun_static.lib`) and one library per OCX: `lib/wfc-mscomctl` (`mscomctl.ocx`; `wfcmscomctl.dll`), `lib/wfc-comdlg32` (`comdlg32.ocx`; `wfccomdlg32.dll`) and `lib/wfc-mswinsck` (`mswinsck.ocx`; `wfcmswinsck.dll`, with the socket layer). Each is a self-contained directory: own CMake, `VERSION`, version resource, member table and the `.inc` behaviour the evaluator includes. The VB intrinsic control tables and the lookups stay in the core (`src/ui`). Each is a submodule of its own repository under `Thewafflication` (`wfc-vbrun`, `wfc-mscomctl`, `wfc-comdlg32`, `wfc-mswinsck`, `wfc-mscomctl2`). |
| Versioning | Every library has its own `VERSION` (0.9.0) stamped into the DLL; the install keeps `lib\<name>\<version>\<arch>`; the launcher takes the highest version and refuses a runtime of another major.minor. |
| Install | `scripts/Install-Wfc.ps1`, run by the package's `.wpm/install.cmd`: administrator installs to `C:\wfc` for all users, otherwise to `C:\wfc\users\<name>`. PATH, `WFC_HOME`, Start menu and Windows Terminal "WFC Command Prompt" (`bin\wfc-prompt.cmd`), Apps & features entry, `-Uninstall`. |
| Static or dynamic | Static (default): the program is a copy of `wfc.exe` plus payload. Dynamic: a copy of `wfcl.exe` plus payload, loading `wfcrt.dll`. `wfc build --link static|dynamic [--bundle]`. OCX libraries: `WFC_OCX_SHARED` builds each as its own DLL. Games are packaged both ways. |
| Command line | `src/cli.cpp`: `help`, `run`, `check`, `build`, `libs`, `env`, unknown-option suggestions, missing-file messages, `--link` validation, exit codes. `wfc build` now carries machine code by default (`--interpret` for the interpreter, `--native` to make a compile error fatal). |
